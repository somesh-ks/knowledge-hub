# The bottom stack on a phone

Ledger section 3, one surface. Read [the core](../design-engineering-ledger.md) first (taste in section 1, how to work in section 2, the phone in section 11). Each row: the ask, what was built, the decision; if a decision and a row disagree, the decision wins.

## The bottom stack on a phone

The navigation bar, the player bar, the floating button, the run indicator and toasts share the bottom edge below 64rem. Every fix so far, in the order it came:

- **Shape** (D31, D72, D86).
  - A bottom bar below 64rem, a side column from 64rem.
  - Tonal, 4rem tall, with a 64x32 pill behind the current icon.
  - The hairline above it removed.
  - The player bar takes the same `surface-container` fill, with no line between, so the two read as one block in both themes.
- **Current tab.**
  - The destinations are Latest, Library and Settings. Today was renamed Latest (2026-10-14); code ids, comments and older entries in this file still say `today`.
  - The current icon is filled and the others outlined, swapped by `aria-current`; the current label takes the full ink (`shell.css:325-370`).
  - Pressing the current tab scrolls to the top, like a native tab bar (D52), and instantly from a keyboard.
  - A press scales only the glyph, never the label.
  - The pressed item lights up before the next page arrives (`navigationBoost.ts`).
- **It stays put** (D52). Hiding the bar on scroll was rejected: Material's navigation bar stays, and the playback controls dock on it.
- **No pull to refresh** (D52). `overscroll-behavior-y: none` is set in CSS (`shell.css:87-91`) because iOS reads it before the first touch. A pull can no longer restart a briefing mid-listen or show a rubber band behind the opaque bars.
- **The old "stuck" player** (2026-10-08). A navigation with the sheet open destroyed its portal while the controller still thought it open. The player became one persisted island with no portal (D32).
- **The pull moves the navigation** (2026-10-11, owner ask).
  - The navigation slides away by `--player-p` as the player rises.
  - It sat a layer under the player (z 20 over 10), so the slide was hidden from the first frame. It now rises above the player while moving and drops back at rest (`shell.css:269-286`).
- **The dock fades with travel.** On a phone it fades by `1 - p/0.3` while riding the page (`player.css:1060-1065`).
- **Floating button** (D52, D59, D60, D77).
  - Create on the Library only. Play on any page with audio, shown only once the hero's Play has scrolled away. Nothing at 64rem and wider.
  - Extended at the top and on scroll up, folded on scroll down.
  - It rides above the navigation, the dock and the run indicator through summed CSS variables, and hides under the open player.
- **Toasts** (2026-10-10 final audit, D90).
  - A toast sits 12px above whichever of the navigation, the dock or the floating button is highest.
  - It had kept the navigation's inset while the player covered it; that is fixed.
  - It lifts over the floating Play only while that button shows.
- **Room under the page.** `scroll-padding-block` counts the bar, the dock and the run indicator, so focus and jumps never land under them (`shell.css:34-57`).
- **Viewport units.**
  - `min-height: 100dvh` follows a collapsing browser toolbar.
  - A launched home-screen app uses `100vh`, because dvh can misreport there before first layout (`shell.css:93-112`).
  - A sticky band keeps the open player clear of the status bar of a home-screen app (D90).
- **iOS 26** clips fixed elements to the inner viewport, so the sheet's backdrop is absolute (`sheets.css:27`). Safe-area insets are mirrored as `--safe-*`, and a window-controls inset covers iPadOS.
- **Native anchoring** (#120, #124).
  - Every element of the stack is held by its bottom edge, and the player box is `100dvh`. The stack now moves with mobile Chrome's address bar in the same frame instead of drifting apart and snapping back.
  - Not verifiable headless; it needs a phone recording.
- **One control, the whole bar** (D102). No chevron; the whole bar opens and closes the player; a keyboard Close exists at every width. The bar's Tab order follows its drawn order (`reading-flow`, D97).
- **Close on a full-screen phone sheet** (owner, 2026-10-22). D152: D144 hid the X on every phone sheet; a full-screen one (`dialog.create-sheet`: New episode, the topic and source panel, Regenerate) shows it again at the row's end, as on a desktop. The partial sheets (menu sheets, the emoji picker, the React drawers) keep no X and close by pull or a tap outside. One selector in `create-sheet.css`, under `SheetHeader.astro`.
- **Create is an action, not a place** (2026-10-08). An agent added it as a navigation tab; the owner made it a solid button, then the floating button. It opens a native `<dialog>`, full screen on a phone and a 28rem panel from 40rem, cloned on first press. A history entry lets Back close it (`createSheet.ts:79-90`). The floating button hides while the player or a dialog is open. "Quite cramped" led to a wider panel with spaced groups and the unlabelled mode switch on top (2026-10-12, D114).
- **Run progress is a line, not a page** ("so we dont take an entire page", 2026-10-08). It sits bottom-left of the side column, or as a thin bar over the player bar on a phone. It persists across moves through `localStorage` (every tab shows it; the old `sessionStorage` key is read once) and `transition:persist`, with `role="status"` (`RunStatus.astro:47`). A failed run shows an alert glyph in the danger colour at the same card height, clamped to two lines; dismissing it sends focus to Create, not to `body`.
- **Run status widget** (plan 1.2, 2026-10-25). Below the stage name sits the time left ("About N min left", "Taking longer than usual" past 1.5 times the stage estimate), shown only when the status route sends `stage_estimates_ms`. A failed stage says what failed and what was kept in one sentence; Details stays the text link. When polling runs out it reads "Lost track of this run" with Check again and Open Library. A run that finishes in a background tab prefixes the title with a dot until the tab is looked at.
- **Mobile strip expands** (2026-10-25). The slim strip above the bottom bar (or the mini player) opens upward on a tap of its line or chevron: message unclamped, time left and buttons on a row of their own. Desktop shows it all and has no chevron.
- **Create sheet to widget morph** (2026-10-25). On starting a run the card arrives from the sheet's centre: a FLIP on transform and opacity only, `--duration-sheet-in` and `--ease-out`, scaled uniformly so its words never stretch. Below 64rem the strip fades in; with reduced motion every width crossfades on `--duration-enter`.
- **One run card for a Regenerate and a Catch up** (owner screenshots, 2026-10-27, D204). The Regenerate sheet had its own six-step stepper and a banner; a failure could not be shown there. The sheet now only starts the run and the card follows it. The card keeps its room in `--run-room`, so the floating button rides above it; Listen now keeps a `--space-2` gutter from the edge; a failed card puts the sentence first and the buttons on their own row. Unticked sheet chips were invisible in the light theme (`--color-surface-overlay` is the sheet's white) and now sit one `--state-hover` step above `--sheet-bg`.
- **Podcast queue** (owner, 2026-10-28 and 2026-10-29, D208, D231): "a simpler way to track the queue of generation on mobile and desktop", "like a file download UI", the queue plan (only a Catch up or a regeneration, never Daily or Weekly), then two rounds of redesign notes. Round 1: stage words, "just shimmer the text", the ring on the left, the finished day kept with Start listening, a divider above the bottom bar, a bigger regular-weight title. Round 3 ("remove marking regeneration attempts", "remove the percentage inside the radial", "have X instead"): the ring is 24px with no percent, so ring and time fit the name and status beside them and everything in a row sits on one centre line and the time under it in whole numbers ("4 min", "40 sec", never "left"); the line under the name is the stage again, so the stage icon, its morph and "(Regeneration)" went; Cancel is an X (`.icon-btn-end`) at the row's end, hidden but keeping its cell at the voices stage; Details says what to do and its Copy button hugs its words. Round 2 took most of it back: the ring 24px with nothing inside and hidden while the dock is open (the percent stays); the title is always "Podcast queue" (a check or alert in place of the ring when over); no stage words and no refresh icon; a failed run's line is one line and Details open a dialog with a copyable snippet; more room between rows and under the head; no Clear queue; on desktop the same logic, with equal padding above the title and below the last row. `Queue.astro` + `QueueRing.astro` + `queue.css` + `scripts/queue.ts` + `scripts/queueDetails.ts`: below 64rem a dock above the bottom bar (the whole 48px row is the button), from 64rem a row under "Updated {date}" opening a popover (`.hero-menu-list.queue-pop`, 26rem, a 20px regular title: headings are never bold, D125). The actions line is always there, so nothing in a row moves (`e2e/queue.spec.ts` holds a row's height). The head's icon cross-fades with a turn between the ring, a check and an alert. The Details dialog is the share dialog's shape; there is no monospace token, so the snippet uses the browser's `pre`. Mistakes on the way: the nav's queue button wore `.app-nav-item`, so navigationBoost fetched `/undefined` (it takes links only now); Try again looked for a button the new rows do not have.
- **A day's Catch ups, Share and section cards** (owner, 2026-10-29, D219): "keep both catchups under same album ... a dropdown selector before the play button", "make sure ... there are no shaking", "if the stack ... overflows the screen make the stack horizontally scrollable", "change share button to an icon button", "big cards for the different topic sections like in the settings page", "the downloaded sign ... next to the subtitle of stories". The select is `.sort-field` at the hero chip's height (`.hero-album`); the row (`.hero-actions`) scrolls with its focus-ring room taken back by margins, to the screen's edges below 40rem; Share is the secondary icon button, `.icon-btn.icon-btn-tonal` (`.hero-share`; the circle on the select's fill, owner, 2026-10-29: "still a circle as a secondary button"); `Chapter.astro` wraps its rows in `.card-group` and the hairlines run full bleed; `HeroDownloaded.astro` is a template that `libraryMenu.ts` copies into the facts line once the page is saved offline. `e2e/catchUpAlbum.spec.ts` holds the row still across a switch.
- **Tablet and phone gaps.** A 56px gap opened under the bar on a tablet while the player was open, and the player's story rows jumped 6px when the story changed; both fixed after screenshot review (2026-10-08).
