## D381: the run state moves to Postgres behind its own switch, saved inside the commit

- Status: amends D300 (step 3)
- Date: 2026-11-06 (the owner, in the audit thread: "go on", then "I'm okay to do the right way")
- Decision: `state/*.json` is kept in the `state_documents` table (one row per file, with a version). With `SINGULARITY_STATE_STORE=postgres` beside `DATABASE_URL`, a command that reads the run state (`run` at its gate, `podcast`, `ingest`, `health`) copies the rows over `state/` before it starts, and `commitAndPush` sends the files the job changed back once the commit is on the remote (commands `run`, `podcast`, `costs`). A save that fails ends the commit as `push_failed` with reason `state_store`, so the run is red; a store that cannot be read stops the command (`health` only warns). A push writes only on the version the pull saw; a moved row is merged by the file's existing rule (costs, podcast timings, usage, run metrics), and a file with no rule (seen, judgments, last run) is refused, never overwritten. The switch is off by default, so merging the code changes nothing.
- Why: the engine commits state to git on every run, which makes content-heavy history and one more place two jobs can collide. The save sits in `commitAndPush`, not in a workflow step, because run.yml's save step is skipped when the commit fails. The audio job never gets the shared `DATABASE_URL` (SEC-03). Its cost ledger moves through a separate Postgres login, `audio_state` (secret `AUDIO_DATABASE_URL`), that row-level security limits to `state/costs-YYYY-MM.json` and `state/usage.json` (docs/runbook.md section 14); the `publish` command pulls and saves only those two kinds of file. With the switch on, `publish` fails closed: no URL or an unreadable store stops the audio job before it spends (a missing ledger would let the budget guard under-count). The rows must be seeded before the switch is on (step 4), or the first push of `usage.json` is refused.
- Rejected: a workflow step for the save (skipped on a failed commit); one switch for config and state (state could not be turned off alone); a recovery record for a push that dies half-way (a rerun rebuilds the files; retrying against old versions can double-count usage).
- Revisit if: a failed save loses something a rerun cannot recreate. Known limits while `state/` is still in git (the switch stays off until they are closed, steps 3c to 5): (1) closed by the audio login once its secret and the workflow change are in (step 3c): the audio job now saves `usage.json` and `costs-*.json` too; until then it writes git only and a pull would revert them, and while both git and the rows carry them a rebase-merged upstream commit and the stored row can each hold the same spend (step 4 seeds and checks); (2) a save that fails after the push leaves the rows behind git, and the next pull would write the old rows over the newer files; (3) the write guard still reads `git status`; (4) a podcast whose only failure is the save is reported as saved, with an error line, because the episode is live and a retry would make a second one.
