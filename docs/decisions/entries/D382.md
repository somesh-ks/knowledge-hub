## D382: the design system becomes its own published library and repository; the repo is renamed `singularityfm-app`

- Status: supersedes D206; amends D254 (the rolling design-system PR becomes a release train), D298 (the app repository carries no licence), D237
- Date: 2026-11-07 (the owner: "I want to split the repo - made my mind, at least for design system, as I want to practice enterprise grade engineering", then answers on decision cards; plan: the owner's repo-split plan, "Agreed decisions" and "Final order")
- Decision: the design system (the `SYSTEM_PATHS` files, `tokens/`, the token and system generators, the `ds` CLI and the style guide) moves to `somesh-ks/singularityfm-design-system` and ships as one MIT-licensed npm package, `@singularityfm/design-system`, published by npm trusted publishing with provenance. The app repository is renamed `singularityfm-app`, carries no licence (readable, all rights reserved) and pins an exact library version. Order: this record; the rename; npm to pnpm; the system's imports into the app are cut; the extraction into `packages/design-system` under an automatic `ds-migration` freeze and a committed codemod; Changesets and a pack-and-install test without publishing; the new repository and its first publish; the app switches; the monorepo copy is deleted a day later; the workspace packages become `@singularityfm/*`. Releases go out weekly or on demand and never with no pending changeset; a canary publishes only for a library PR labelled `canary`; the thread merges green patch and minor bump PRs and the owner merges breaking ones. `SINGULARITY_*` variables, storage keys and the CLI keep their names. Admin moves to a private repository in a later track.
- Why: the owner wants to practise the producer and consumer side of a versioned package. `@singularity` on npm belongs to another maintainer, so the scope is `@singularityfm`, and the repositories share the prefix. npm trusted publishing trusts one named repository and workflow, so the rename comes first and the first publish happens from the library repository.
- Cost: a component fix for the app needs a library PR, a release (or a canary) and an app bump PR; 99 of 261 commits on main in the 7 days to 6 Nov touched the design layer. Two CodeRabbit reviews per cross-repository change, a second Vercel project, and Claude threads that need both repositories.
- Rejected: keeping one repository (the owner chose the practice); two packages, tokens and components (one package with a tokens subpath needs half the release machinery); a release per merge or at five changes (D375 already batches deploys, and publishing is free); a hand-picked window for the extraction (the owner wants it automatic).
- Tooling: Vercel installs with the pinned `pnpm@10.34.9` through `npx` (no project setting needed); worktrees run `pnpm install --frozen-lockfile --offline`, so `worktreeLinks.mjs` is removed.
- Revisit if: the library sees no release for a month (then it is changing too little to need its own repository), or a bump PR breaks production.
