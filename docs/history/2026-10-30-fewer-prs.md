# Fewer PRs

2026-10-30. The owner: "I feel there are way too many PRs being raised instead of combining many changes into one."

## What happened

A day of threads each opened a PR, and every feature that touched a shared component opened a second one under D237. That spent CodeRabbit's reviews (about 10 an hour), Vercel's 100 deploys per 24 hours and the owner's hand-merge queue.

## What changed

D254: one PR per task per thread, review fixes on the same branch, one rolling `design-system` PR at a time, small fixes batched. It is in `AGENTS.md`, the PR template (a "Batching" section) and the project instructions. The owner also asked for the same rule in his user-level Claude Code instructions; those live on his machine and are not in the repository.
