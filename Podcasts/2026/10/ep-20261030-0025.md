# Design engineering craft

Hello, and welcome to Singularity. Today: design tokens get a stable open standard. A team makes its interface more consistent by deleting tokens. And the author of Sonner explains why toasts work better on transitions than keyframes.

The Design Tokens Community Group has published the first stable Design Tokens specification. It is numbered 2025.10, and it came out on October 28, 2025. More than twenty editors and authors built it as a vendor-neutral file format. Figma, Sketch and Framer support it or are implementing it. That matters because each tool used to speak its own dialect, so moving between them meant rewriting. Syncing is still the weak link. In Supernova's 2024 survey, 44.4% of teams ran design-to-code by hand, against 31.4% automated.

A team found that everyone only partly followed its color palette, so it rebuilt its design tokens. First, it renamed tokens by intent, such as surface-raised and text-muted, instead of by hue, such as gray-200. Then it deleted every token that had no usages. It also added a CI check, an automated test, that fails on raw hex values in components. The system now feels smaller and easier to extend. Fewer options made the interface more consistent. The write-up appeared on DEV Community.

Emil Kowalski has written up how he built Sonner, a toast library that npm now reports at over 40 million downloads a week. He first used CSS keyframes. Keyframes cannot be interrupted, so older toasts jumped when new ones arrived. He switched to CSS transitions, which can be retargeted mid-motion. The newer @starting-style rule could simplify the code. He has only said he might update it soon.

That's Singularity for today. Thanks for listening.
